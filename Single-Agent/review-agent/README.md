# LifeOS Review Agent 🛡️

Production-Ready Quality Assurance (QA) & Verification Layer for the **LifeOS Multi-Agent System**.

The **Review Agent** is responsible for validating, reviewing, verifying, and scoring outputs generated by every other AI agent (**Research Agent**, **Planning Agent**, **Memory Agent**, **Execution Agent**, **Communication Agent**, **Chief of Staff**) before results are accepted into the ecosystem.

---

## 🌟 Key Capabilities

The Review Agent ensures every output is:
- ✅ **Correct** & Accurately structured
- 🧩 **Complete** without missing keys or unclosed fences
- 🔒 **Secure** (Scans for SQL injection, hardcoded API keys/passwords, `eval()` calls)
- ⚖️ **Consistent** & Logically coherent (Detects self-contradictions & hallucinations)
- 📊 **Scored** on a multi-criteria 0–100 quality scale

### 🎯 Approval Rule Engine
- **Quality Score &ge; 80**: Approved output (`"status": "approved"`)
- **Quality Score < 80**: Rejected output (`"status": "rejected"`)

### 📋 Guaranteed Standard Output Format
All review endpoints strictly return JSON adhering to:
```json
{
  "status": "approved",
  "quality_score": 95,
  "confidence": 0.98,
  "issues": [
    {
      "code": "MISSING_KEY",
      "severity": "high",
      "message": "Required key 'result' missing in JSON response",
      "field": "result",
      "suggestion": "Include key 'result' in response."
    }
  ],
  "warnings": [
    "Consider adding inline references for paragraph 3."
  ],
  "suggestions": [
    "Add a summary section at top of document."
  ],
  "summary": "Output meets all key criteria with minor formatting suggestions."
}
```

## 🏗️ System Architecture & Tech Stack

### Tech Stack
- **Backend**: Python 3.12, FastAPI, Async SQLAlchemy 2.0, PostgreSQL, Alembic, Pydantic v2, Pytest
- **AI Integration**: Gemini 2.5 Flash API with deterministic offline rule engine fallback
- **Frontend**: React 18, TypeScript, Vite, Tailwind CSS, Lucide Icons, Recharts, React Query
- **Security**: JWT Authentication (HS256), Passlib (Bcrypt), Role Based Access
- **Containerization**: Docker, Docker Compose, Nginx

## 🗄️ Database Schema

The PostgreSQL database manages 7 primary tables:
1. `users`: System reviewers & administrator accounts.
2. `reviews`: Full history of QA evaluation records, quality scores, status, issues, and payload JSONs.
3. `review_logs`: Operational execution & audit logs.
4. `quality_scores`: Granular 11-criteria quality score breakdowns.
5. `review_rules`: Customizable rule policies and quality thresholds.
6. `review_history`: Change tracking and re-review versioning.
7. `agent_reviews`: Aggregated performance metrics per agent.

## 🔌 REST API Endpoints

### Authentication
- `POST /api/v1/auth/register` - Register reviewer account
- `POST /api/v1/auth/login` - Obtain JWT access token
- `GET /api/v1/auth/me` - Get current user profile

### QA Review Operations
- `POST /api/v1/review` - Universal Agent Review
- `POST /api/v1/review/code` - Code Review (Python, Java, JS, TS, HTML, CSS, SQL)
- `POST /api/v1/review/json` - JSON Validation & Schema Integrity Review
- `POST /api/v1/review/document` - Document & Markdown Structure Review
- `POST /api/v1/review/research` - Research Findings & Source Citation Review
- `POST /api/v1/review/execution` - Execution Output & DB Script Review
- `POST /api/v1/review/planning` - Planning & Milestone Breakdown Review
- `GET /api/v1/review/history` - Searchable & filterable paginated audit history
- `GET /api/v1/review/{id}` - Detailed review record with criteria breakdown
- `DELETE /api/v1/review/{id}` - Delete review record

### Analytics & Rules
- `GET /api/v1/analytics/dashboard` - Dashboard KPIs, agent performance matrix & quality distribution
- `GET /api/v1/analytics/quality` - Quality distribution breakdown
- `GET /api/v1/rules` & `POST /api/v1/rules` - Rule policy management
- `GET /api/v1/health` - System health check

## 🚀 Quick Start & Running Locally

### Option 1: Docker Compose (Recommended)
```bash
docker-compose up --build
```
Access the application:
- **Frontend Dashboard**: `http://localhost:3000` (or `http://localhost:5173`)
- **Backend Swagger API Docs**: `http://localhost:8000/docs`

### Option 2: Run Backend & Frontend Independently

#### 1. Backend Setup
```bash
cd review-agent/backend
python -m venv venv
source venv/bin/activate  # On Windows: venv\Scripts\activate
pip install -r requirements.txt

# Run FastAPI backend server
uvicorn app.main:app --reload --port 8000
```

#### 2. Run Backend Tests
```bash
cd review-agent/backend
pytest tests/ -v
```

#### 3. Frontend Setup
```bash
cd review-agent/frontend
npm install
npm run dev
```
